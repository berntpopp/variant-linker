# Variant-Linker repository audit — 11 September 2026

The highest-priority problems are silent data corruption: caching can substitute another variant's annotation, multiallelic handling can assign inheritance to an absent allele, and VCF output loses sample data. Fix these before optimizing throughput or relying on the current tests as a release gate.

Reviewed commit: `ee861a8d45d540b0042573fe7fb6982445299ced`. Scope: 34 source JavaScript files, 31 test files, configuration, scoring models, browser packaging, benchmarks, dependency locks, and GitHub workflows. Three parallel reviewers covered correctness, API/cache reliability, and security/release engineering; the coordinating reviewer examined orchestration, streaming, features, packaging, and reproduced important findings independently. Application code was not changed.

P1 means fix before depending on the affected functionality; P2 means substantial reliability, security, or compatibility work; P3 means lower-priority hardening. Priorities reflect demonstrated impact and exposure, not just theoretical severity. Security preconditions are stated explicitly.

**P1 findings: data correctness and unsafe failure modes**

**1. POST cache keys ignore the request body.** `src/apiHelper.js:120–125,212–214` reads/writes only the URL. VEP and recoder POST requests share a URL across different variant bodies. Reproduction with 201 distinct VEP inputs and caching enabled returned **400 annotations, 200 unique inputs, one HTTP request**, and omitted input 201. This also affects repeated single-variant requests using the same options. Cache identity must include method, canonical URL/query, body, and assembly/server identity. Add different-body, cross-assembly, and 200/201 boundary tests; invalidate old cache entries when changing the key scheme.

**2. Multiallelic genotypes are copied to every split allele.** `src/vcfReader.js:152,226–227`; `src/inheritance/genotypeUtils.js:33,62`. For `REF=A, ALT=C,G`, child `0/1`, parents `0/0`, both C and G records retain child `0/1` and both receive `de_novo`, although the child has no G allele. Calls such as `0/2`, `1/2`, and `2/2` are also not properly classified. Preserve each ALT index and parse genotypes into allele arrays with explicit ploidy, phase, and missingness; evaluate target-allele dosage instead of copying diploid binary strings. [VCF genotype specification](https://samtools.github.io/hts-specs/VCFv4.5.pdf).

**3. VCF serialization discards all FORMAT/sample columns.** `src/vcfFormatter.js:22–26,492–502`. A real parser/formatter round trip produced a **12-column trio header and an eight-column record**. GT, AD, DP, GQ, PL, and phase information disappear. Preserve original record/sample columns and change only annotation fields. Validate exact sample preservation with an independent VCF reader, including multi-sample and phased inputs. [VCF header and genotype requirements](https://samtools.github.io/hts-specs/VCFv4.5.pdf).

**4. Distinct VCF records at one site are merged with incorrect metadata.** `src/vcfFormatter.js:165,199–204,396,476–489`. Two A>C and A>G rows at the same position with different IDs, QUAL, FILTER, and AF become one `ALT=C,G` row retaining only the first row's QUAL and `AF=0.1`; a second-row `q10` failure disappears. ID arrays serialize with commas instead of semicolons, and `FILTER=.` becomes `PASS`. Preserve original record identity; any intentional merge needs explicit allele-aware INFO/FORMAT rules. VCF distinguishes missing filter evaluation from passing and defines allele-dependent field cardinality. [VCF specification](https://samtools.github.io/hts-specs/VCFv4.5.pdf).

**5. Liftover transforms coordinates without correctly transforming variants.** `src/assemblyConverter.js:103–119`; `src/variantLinkerCore.js:676–685`. An A>C SNV mapped to strand -1 remains A>C, rather than reverse-complemented T>G. An `ATG>A` deletion at 100 maps only `1:100-100`, so a mapping cannot establish continuity across the deleted span. Use a validated variant-liftover implementation, or map the full reference span, handle orientation/anchoring, normalize, verify target REF, and reject incomplete mappings. [Ensembl coordinate mapper](https://rest.ensembl.org/documentation/info/assembly_map), [Broad's variant-liftover behavior](https://gatk.broadinstitute.org/hc/en-us/articles/360036733851-LiftoverVcf-Picard).

**6. Assembly selection is process-global and differs between library and CLI.** `src/assemblyConverter.js:28–43`; `src/apiHelper.js:116`; `src/main.js:515–516`. Liftover temporarily mutates `process.env.ENSEMBL_BASE_URL` across an `await`. Holding a liftover request open caused an unrelated default-GRCh38 annotation to use the GRCh37 host. Separately, calling the library's `analyzeVariant({variant:'1-100-A-C',assembly:'hg19'})` with no environment override still sent its request to `https://rest.ensembl.org`, because ordinary assembly selection is implemented in the CLI rather than the core. Both behaviors were reproduced with mocked Axios. Pass immutable per-request endpoint/assembly options through the client; do not switch process-global state. Test library/CLI parity, concurrent opposite-assembly requests, and out-of-order completion.

**7. Ambiguous parental calls become confirmed compound heterozygosity.** `src/inheritance/compoundHetAnalyzer.js:176–186,216–220`; `src/inheritance/inheritanceAnalyzer.js:266`. With child `0/1` at both sites, father `0/1`/missing and mother missing/`0/1`, the analyzer sets `isCompHet:true`, prioritizes compound heterozygosity, and reports `segregates`, while simultaneously listing both keys as ambiguous. Opposite parental origin is not established by these inputs. Separate tentative and established origins; confirmation requires sufficient opposite-origin or phase evidence. Propagate uncertainty into segregation status, not just auxiliary details.

**8. Failed streaming chunks disappear with successful process status.** `src/main.js:545–568,634–637`. A mocked API failure in the actual CLI produced empty stdout, an error on stderr, and **exit code 0**. Failure in the first chunk also advances the first-header flag, potentially suppressing a later successful header. Default to nonzero completion for failed inputs; if partial output is supported, emit structured failure accounting and a documented status. Set header state only after writing a header successfully.

**9. Persistent-cache maintenance can delete unrelated JSON files.** `src/cache/PersistentCache.js:203–205,286–295,311–325`. Every `.json` file in the configured directory is treated as cache data. A mock-only probe showed cleanup deleting `unrelated-project-config.json` because it lacked cache metadata. This requires persistent caching to be enabled and its directory to overlap other data; default configuration disables it. Use an application-owned subdirectory and verify cache filename/schema/ownership before deletion. Never delete arbitrary invalid JSON.

**P2 findings: correctness, compatibility, and reliability**

**10. Streaming tabular output ignores filters and changes column counts.** `src/main.js:551`; `src/variantLinkerCore.js:1126–1150`; `src/variantLinkerProcessor.js:395–428`. The core parses the filter but skips CSV/TSV formatting during streaming; the CLI formatter then receives `null` instead of that filter. A `stop_gained` filter emitted a mocked `missense_variant`. Columns are also inferred independently per chunk: SNV then CNV with `--chunk-size 1` produced widths **21,21,25** for header and two rows. Apply selection once before serialization, and freeze the output schema for the whole stream.

**11. Combining pick-output and filtering restores discarded transcripts.** `src/variantLinkerProcessor.js:283–292,337–371`. The pick step updates `filteredResults`, but object filters start again from `results.annotationData`. A two-transcript probe returns both `picked` and `other` when pick-output is combined with a matching top-level filter. Compose transformations on the current result and avoid mutating caller-owned annotations or metadata.

**12. BED annotation fails with the actual installed dependency; coordinate boundaries are also wrong.** `src/featureParser.js:12,189,201`; `src/featureAnnotator.js:39–53`. `require('node-interval-tree')` returns an object, so loading a real BED file throws `IntervalTree is not a constructor`. Tests replace it with a constructor stub. After substituting only the correct `.default` import in memory, BED `[100,200)` incorrectly matched VEP position 100; its one-based span is 101–200. Returned metadata also lacks `region_start/end` because interval coordinates are not included in the stored payload. Correct the import, normalize coordinates explicitly, and test real dependency boundaries. [UCSC BED coordinates](https://genome.ucsc.edu/FAQ/FAQformat.html#format1).

**13. Valid haploid genotypes are not recognized.** `src/inheritance/genotypeUtils.js:18–21,46–65`. `isVariant('1')`, `isRef('0')`, and `isMissing('1')` all return false. A haploid X example yields `unknown_missing_genotype`. Parse ploidy independently from biological inference, then apply chromosome/sex/PAR rules. Add haploid, mixed-ploidy, and partially missing examples. [VCF ploidy representation](https://samtools.github.io/hts-specs/VCFv4.5.pdf).

**14. Scoring can abort a batch on valid transcript-free annotations.** `src/scoring.js:225–227,381–386,459–463`. A declared transcript variable with default 0 is never initialized when transcripts are absent, causing `cadd is not defined`. The bundled nephro model on an intergenic annotation throws `consequence_terms_variant.map is not a function`: an empty unique aggregate becomes numeric 0. Initialize every declared variable, preserve aggregate types, and define an explicit unscorable outcome when a model does not apply. Test every bundled configuration on empty/intergenic and mixed batches.

**15. MANE priority uses a synthetic field.** `src/scoring.js:340–345` checks `mane === 1`, ignoring an actual `mane_select` value. A later MANE Select transcript loses to an earlier canonical transcript. Define Select/Plus Clinical precedence using real API fields and replace synthetic priority fixtures. [Ensembl VEP MANE options](https://mart.ensembl.org/info/docs/tools/vep/script/vep_options.html).

**16. SCHEMA output fails its own schema.** `src/variantLinkerCore.js:1043–1051,1119–1123`; `schema/variant_annotation.schema.json:12–24`; `src/schemaMapper.js:15–17`. A single mocked successful annotation fails for missing `meta.inputFormat` and `meta.recoderCalled`; batch `meta.input` is also an array while the schema expects a string. The mapping function is a no-op. Define/version the actual output contract, implement the promised mapping or rename the mode, and compile/import the schema statically.

**17. Browser exports load, but API use fails.** `src/apiHelper.js:116`; `webpack.config.js`; `package.json` files allowlist. A browser-like VM can load the built UMD module, but `apiHelper.fetchApi()` immediately rejects with `process is not defined`. Packaging also excludes `dist/variant-linker.bundle.js`. Separate browser-safe and Node entrypoints, inject environment configuration, and verify a real browser HTTP flow plus the packed artifact. The VM probe is narrower than a real browser E2E test.

**18. HTTP retries have no deadline or cancellation.** `src/apiHelper.js:193–201`. Axios gets headers/proxy but no timeout, signal, or response-size limit; the installed default timeout is 0. A stalled request never reaches the retry loop. Add per-request timeout, overall retry budget, caller cancellation, response bounds, and capped Retry-After delays. Classify retryable network errors explicitly.

**19. Large recoder batches corrupt stdout with debug messages.** `src/variantRecoderPost.js:86–131`. More than 200 inputs take a path with unconditional `console.log` before, during, and after requests. JSON/CSV consumers receive debug lines without enabling debugging. Route diagnostic messages through the debug logger/stderr and test the complete CLI stdout as the selected output format.

**20. API results are joined to inputs by array index.** `src/variantLinkerCore.js:376,440,483,565,819`. A mocked reordered VEP response assigned key `1-100-A-C` to input `1 200 . A G . . .`, and vice versa. This demonstrates fragility under reordered/omitted responses; this audit did not establish that Ensembl normally reorders successful responses. Match echoed input/stable request identities, validate cardinality, and account explicitly for unmatched/duplicate/error entries.

**Security and release engineering**

**21. Releases are not gated on the tested artifact, and workflows discard locks.** P1. `.github/workflows/release.yml:3,15,31–44` independently triggers install/build/publish on main; lint/tests live in another workflow. CI, release, and docs workflows delete lockfiles before `npm install --legacy-peer-deps`. The same commit may be tested and released with different dependency trees. Use reviewed root/docs locks with `npm ci`; have release depend on successful verification and publish that exact artifact. Branch protection was not inspected, so this is a workflow-level finding.

**22. Dependency audits report unresolved vulnerabilities.** P2; exposure varies by dependency and feature. Snapshot:

| Dependency scope                           | Critical | High | Moderate | Low | Total affected records |
| ------------------------------------------ | -------: | ---: | -------: | --: | ---------------------: |
| Root including development/release tooling |        4 |   29 |       16 |   4 |                     53 |
| Root production only                       |        0 |    3 |        2 |   0 |                      5 |
| Documentation                              |        0 |    5 |        2 |   0 |                      7 |

These are affected dependency records, not demonstrated application exploits. Production records include Axios, Ajv, fast-uri, follow-redirects, and form-data. Prioritize production upgrades, then release/dev-server/docs tooling; rerun audits and compatibility checks. The verified Axios proxy-redirect advisory requires authenticated proxy settings and a redirecting endpoint; default Ensembl traffic alone does not establish exploitability. The webpack-dev-server advisory concerns a running development server and a malicious website, not the static deployed docs. The four critical records are development/release dependencies. [Axios maintainer advisory](https://github.com/axios/axios/security/advisories/GHSA-j5f8-grm9-p9fc), [webpack-dev-server maintainer advisory](https://github.com/webpack/webpack-dev-server/security/advisories/GHSA-9jgg-88mc-972h).

**23. Scoring JSON is executable code.** P2, conditional trust boundary. `src/scoring.js:156,310` uses `new Function` for conditions/formulas. A harmless formula set a global marker and returned 42. This requires control of accepted scoring configuration; no remote code execution from ordinary variant/API data was demonstrated. Document the trust contract prominently and use an allowlisted expression interpreter for any untrusted configuration. Do not represent JSON parsing as making formulas safe.

**24. Diagnostics/exports need explicit data handling.** P2/P3. `apiHelper.js:83` includes the full malformed proxy URL in an error, exposing embedded credentials even without debug; redact userinfo. Debug paths print variants and sample identities, and cache entries contain plaintext data: make payload logging explicit and use restrictive cache permissions. `dataExtractor.js:586–595` permits spreadsheet formula cells and unescaped TSV tabs/newlines; offer spreadsheet-safe output and define reversible TSV escaping. Spreadsheet exploitation requires opening attacker-controlled cells in a capable spreadsheet application. No shell execution was found in `src`, and no CLI shell-injection finding is warranted.

**25. Runtime support and workflow permissions are inconsistent.** P2/P3. `package.json` promises Node >=14, but locked lru-cache requires `20 || >=22`; CI only lists 18/20. Choose an explicit supported runtime matrix and test its minimum. Pin external actions to reviewed commits; restrict build jobs to read access and grant publishing permissions only where needed. [GitHub secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use).

**Why the existing tests miss these failures**

- Cache tests cover repeated GETs, while POST tests disable caching (`test/apiHelper.test.js:114–151`).
- Multiallelic tests check that genotype data exists, not target-allele values (`test/vcfReader.test.js:76–78`).
- BED unit and integration tests replace the real interval-tree export with a callable stub (`test/featureParser.test.js:276–280`; `test/feature-annotation-integration.test.js:29–40`).
- Liftover mapping fixtures use positive strand; MANE-priority tests invent `mane:1` instead of using real API fields.
- `test/streaming.test.js:42–61` installs nock in the parent and spawns the CLI in a separate process. Those mocks do not intercept the child; assertions even expect the real gene OR4F5 rather than the TEST_GENE stub. Several other integration tests call live services. Slow/flaky API behavior therefore affects routine verification.
- Baseline-format comparisons are useful but cannot establish sample preservation, allele identity, negative-strand correctness, or absence of data loss without explicit invariants.

Build an offline contract suite using a local HTTP fixture server or child-process preloads; disable unintended network access. Keep a separate, opt-in live API smoke suite. Favor real parser/dependency boundary tests over mocks that duplicate assumptions. Add browser and packed-package smoke tests. Required invariants should include: every input has an accounted outcome; every annotation matches its input; original VCF samples survive; selected filters apply identically across formats; output columns remain stable; failure exit codes reflect lost work.

**Recommended implementation order**

1. **Contain silent corruption:** fix POST keys and response matching, preserve VCF records/sample fields, implement allele-aware genotypes, correct liftover and uncertain inheritance, and make partial failures visible. Gate release on these regression tests.
2. **Repair advertised behavior:** fix streaming filters/schema, BED integration, transcript-free scoring/MANE selection, SCHEMA mode, browser entrypoints, and distribution contents. Normalize CLI/config/library options into one validated request model.
3. **Harden the client/cache:** immutable endpoint options, timeout/cancellation, async L2 reads, ownership-safe deletion, byte budgets, unique temp writes, and amortized cleanup. Expose cache/retry/error metrics.
4. **Make checks reproducible:** npm ci, aligned engine/CI matrix, offline contract tests plus optional live tests, exact-artifact release gating, and reviewed dependency upgrades.
5. **Optimize measured bottlenecks:** bounded streaming, backpressure, compiled expressions, guarded logging, request coalescing, then rate-aware concurrency. Verify correctness invariants alongside throughput/RSS measurements.

Architecturally, a single normalized variant/record identity and immutable analysis context would remove much of the duplicated single/batch/VCF routing and global state. Separate acquisition, annotation, biological inference, filtering, and serialization; make the library return one stable result type and let serializers own strings/streams. This directly addresses the currently divergent behaviors rather than requiring a wholesale rewrite.

**Remaining hypotheses, not promoted to confirmed findings**

- VCF input plus liftover appears to leave genotype/original-record maps keyed by pre-liftover coordinates while annotations use lifted keys (`variantLinkerCore.js:819–828,882–885,1078–1089`). Add an end-to-end regression before changing it.
- Compound-het grouping only uses the first transcript's gene (`inheritanceAnalyzer.js:106–113`), potentially missing pairs associated with other overlapping genes.
- A live Ensembl response-order guarantee, production cache scale, deployed workflow settings, and clinical/scientific validation remain outside the evidence gathered here.
